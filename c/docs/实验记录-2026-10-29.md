# 成员 C 开发实验记录 · 2026-10-29

本次完成了本地检索模式的 Q0/Q1 对照、后端回归测试和真实本机 HTTP 验证。没有配置或调用真实聊天/向量模型，因此未测量生成式问答正确率或语义支持率。

## 环境与样本

- Windows，Python 3.12.14；依赖版本见 `requirements.lock.txt`。
- 流程版本 `1.2`，提示词版本 `qa-evidence-v1`。
- 原创小说《灯塔旧账》，6 章，规范化输入共 1449 字符。
- 20 条开发题：14 条在给定进度内可答，6 条不可答；含事实、动机、别名、未知信息和证词冲突。
- A/B 示例记录共 3 条，分别为事件时序、并存关系和后期确认的别名。
- Q0 使用原文；Q1 允许使用当前可见的 A/B 记录。两组各 20 个请求，同一本书、同一问题和进度；模式顺序按题交替。
- 问答结果均为 `extractive`，聊天与向量 API 尝试调用数均为 0，无模型调用费用。

此小说与题目用于开发和回归，不能作为独立留出集；尤其全文仅 1449 字符，小于 6000 字符上下文上限，难以体现长篇检索与结构化知识的优势。

耗时来自进程内 FastAPI 测试客户端，包含本机 SQLite 与检索操作，不能作为公网延迟或大模型性能数据。每次新上传小说，问答缓存命中数为 0；首次分词初始化等因素仍影响耗时。

这里的“14 / 14”只说明候选原文包含全部预设关键词。它不是 100% 问答准确率，也不验证否定、因果、归属或推断正确。所有结果的 `claims` 为空，状态为 `partial`，表示待阅读的候选原文；不可答题也可能返回相关片段。

两组在所测自动指标上相同，本次实验未证明 Q1 带来质量提升，也不能据此证明结构化知识没有价值。要比较其作用，需要更长、跨章节的信息需求和真实生成答案，并进行人工盲评。

## 工程验证

最终完整测试结果为 **118 passed**，无失败；另有 1 条 Starlette 测试客户端关于 HTTPX 的依赖弃用提示，不影响本次通过结果。JUnit 记录保存在 `evaluation/results/development-20261029/tests.xml`。

后端测试覆盖分章/分块、原文偏移、跨书隔离、进度回退、A/B 历史版本、缓存变化、无效引用、支持性复核结果处理、技术错误、调用上限与模型适配器。模型响应采用模拟数据，测试的是控制流程，不代表真实模型语义能力。

本次发现并修复了四类实际问题：

1. “这是”等泛化词被当成检索依据；补充分词停用词，并使用正值 IDF 改善少量已读片段的 BM25 评分。
2. 引用字段自动去除边界空格，使正文切片与起止坐标不一致；引用模型改为精确保留字符串。
3. 短段落过多导致重复定位元数据使模型上下文膨胀；模型输入精简为编号、章节和原文，最多 64 条证据，原文与结构文本合计最多 6000 字符。
4. A/B 记录 ID 和版本包含冒号时可能碰撞；对组成部分编码后构造稳定键。

向量请求另按最多 32 条一批发送，150 个可见片段的模拟测试验证了分批行为和未来章节隔离。

`scripts/smoke_http.py` 已通过真实回环 HTTP 验证：启动独立临时 Uvicorn 服务，检查 Bearer 认证、TXT multipart 上传、问答、3 条原文引用的精确切片、越界段落拒绝访问、答案缓存、模型调用数为 0。临时服务和数据库在完成后清理。

## 完成真实模型实验所需步骤

在 `.env` 填入已有兼容服务的地址、密钥和模型名称后，使用 `--in-process --qa-mode llm` 或连接配置好的后端运行同一套题。API 密钥不需要提交代码或发到聊天。真实模型的进程内实验沿用配置的持久 `DATA_DIR`，与使用同一数据目录的服务共享每日调用计数，重复启动不会重置额度；实际费用仍以服务账单核对。

正式结题应另准备独立小说的留出题集，建议 120 个问题进度样本，包含当前可答、仅后文可答和全书无法回答的情况。由两名成员盲评正确性、逐条证据支持和语义剧透，再报告 Q0/Q1 差异。当前材料可以用于工程实现与开发实验章节，不能替代这部分真实模型与人工评审结果。
