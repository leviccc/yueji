# 《孤独者》关系抽取评测（v4）

> 这是开发集上的历史探索性结果。`normalize.py` 固定了《孤独者》的人物名称、人物编号和关系标签映射；后处理规则也在同一材料上调整。因此下面的指标不能作为新小说上的独立测试结果，也不代表网页中人工复核后图谱的端到端指标。标注来源和人工复核情况未得到独立核验，不能将其视为经人工认证的正式金标准；历史实验也不能代表当前提示词和人物上下文版本的表现。

## 口径

- 样本：`guduzhe_dev`，《孤独者》全五节，12195 字，148 段。
- **gold**：`gold_guduzhe.json`，开发阶段整理的 32 条关系，标签取自 `taxonomy.md`；原文件未记录标注者或复核信息，只标注双方都能落到人物 ID 的关系，未命名的次要角色（如堂兄的小儿子）不计入。
- **predictions**：`predictions_guduzhe.json`，模型关系候选依次经过四级后处理：`dialogue.py` 引语说话人归属 → `normalize.py` 统一人物 ID 与标签 → `dedupe.py` 断言去重 → `filters.py` 丢弃事件类断言。**没有**用人工复核结果做筛选，评测的是「模型 + 证据校验 + 后处理」这一层。
- `progress_chapter` 取关系被获知的章节。

## 有效改动 1：引语说话人归属（`dialogue.py`）

第 3 节 p27–p29 是连殳在引号内追述童年，句中的「我」是连殳而不是叙述者。v1 里模型把「我」直接当成叙述者，导致 `zumu→wo 关切`、`wo→zumu 疏远` 两条误报和对应的两条漏报，第 3 节 P/R 只有 0.286/0.333。

规则：

1. **引号奇偶判定外层**：段落中「X 说/道」若位于引号外（引号计数为偶），才算外层说话人；引号内的（如 p28「女工总指了一幅像说」）是嵌套引语，不覆盖外层。
2. **连续引语块继承**：紧跟已归属引语的连续引语段落继承同一说话人（p27 → p28 → p29）。
3. **代词消解**：`他/她` 取本章最近一个引号外、非「他/她/我/你＋称谓」的称谓；名字匹配按最长优先，避免把「大良」从「大良们的祖母」里截出来。
4. **只改叙述者**：仅当候选的 `source`/`target` 是「我」且该段说话人不是叙述者时才替换；判不出的引语保留原样交人工复核。

效果：两条候选被正确重映射为 `zumu→wei_lianzhu 关切`、`wei_lianzhu→zumu 疏远`，第 3 节 P/R 升到 0.571/0.667，总体 F1 0.758 → 0.818，零额外 API 调用。

## 有效改动 2：跨章断言去重（`dedupe.py`）

模型会在不同章节反复断言同一件事（「我—魏连殳 相识」在第 2、3 节各出现一次，「祖孙」在第 3 节重抽）。

- **持久关系**（祖孙、亲子、继亲、兄弟、叔侄、过继、其他亲属、相识、雇佣、租佃、顾问、关切、疏远、怀疑、感激）：同一对人物只保留**最早获知**的一条。
- **事件关系**（往来、通信、赠予、劝慰、请托、帮助、冲突、其他）：每次发生都是独立断言，不去重——否则第 2、3、5 节三次探访会被压成一条，召回直接掉。
- 无向关系对调双方视为同一断言，有向关系方向相反不算重复。

效果：预测 34 → 31，误报 7 → 4，精确率 0.794 → 0.871，F1 0.818 → 0.857。

## 有效改动 3：事件过滤（`filters.py`）

此开发集评测中，「其他」桶包含一次性动作、意图和身份指认（指认画像、询问存款、回信意愿）。`filters.py` 在评测预测导出前丢弃这些断言；该评测脚本不直接修改网页图谱，图谱以人工接受的记录为准。

效果：预测 31 → 28，误报 4 → 1，精确率 0.871 → 0.964，F1 0.857 → **0.900**。剩下的唯一误报是标注口径问题（见下）。

## 提示词实验：引语指代（否定结果）

在写后处理之前，先试了两版提示词，均用数据库副本重抽第 3 节。

| 版本 | 提示词改动 | 第 3 节 TP/FP/FN | 总体 P | 总体 R | 总体 F1 |
|---|---|---|---|---|---|
| 基线 | 无 | 2 / 5 / 4 | 0.735 | 0.781 | 0.758 |
| A | 引语中「我」= 说话人 + 不拼接复合称谓 | 1 / 6 / 5 | 约 0.71 | 约 0.75 | 约 0.73 |
| B | 仅不拼接复合称谓 | 2 / 8 / 4 | 0.676 | 0.781 | 0.725 |

结论：提示词约束没有解决说话人归属，且会挤压召回或放大事件型输出；提示词已回退到基线，改用确定性后处理。实验成本 4 次 API 调用。

## 剩余错误（v4）

### 误报（1 条）

- `tangxiong→tangxiong_son 亲子`（第 2 节）：原文只说「他的小儿子」，人物未命名，gold 不收未命名角色，属标注口径差异。

### 漏报（5 条）

- `zumu—nvgong 雇佣`（第 1 节「雇一名女工」）。
- `fuqin—wei_lianzhu 亲子`、`muqin—wei_lianzhu 亲子`（第 3 节）：人物抽到了，关系没抽到。
- `shisan_daren→wei_lianzhu 怀疑`（第 5 节「疑心他装出来的」）：模型抽的是相邻的「询问存款」。
- `wo→wei_lianzhu 往来`（第 5 节回 S 城后去看他）。

## 工程补充：候选关联到已有人物

复核时可能遇到模型将同一人物的不同称谓识别为独立人物。当前接口的 `link_to_person_id` 需要同时提交身份揭示段落和引文；系统保留揭示前的独立人物，从身份依据章节起建立合并。系统只校验引文存在，身份是否相同仍须人工判断。这个实现是后续工程改动，不属于上表历史实验的评测条件。

## 结论

- 四级后处理把总体 F1 从 0.758 抬到 0.900，其中说话人归属 +0.060、断言去重 +0.039、事件过滤 +0.043，全部无额外 API 成本。
- 精确率已到 0.964，瓶颈转移到召回（0.844）：5 条漏报全是模型没抽到的关系，后处理无法补。
- 在这次开发样本的两次提示词尝试中，指标没有改善；不能据此断定其他提示词或其他小说上的效果。可考虑补充抽取策略（分句级重抽、亲属称谓规则或第二遍校验），但需在独立样本上验证。

## 局限

- gold 共 32 条，文件未记录标注者和复核过程，无法确认其独立性与人工复核情况，只能用于开发参考。
- 只评关系，不评人物识别、别名、合并与阅读进度语义。
- 后处理规则基于本样本的文体特征（引号、说话动词、亲属称谓、事件标签），换作者或叙述风格需要重新验证。
- 事件过滤依赖「其他」桶的判定，等于把事件识别的责任前移到了归一化阶段；如果模型把事件标成看似合理的关系标签，过滤器不会拦住。
- 评测可复现：`python normalize.py && python evaluate.py gold_guduzhe.json predictions_guduzhe.json`。
